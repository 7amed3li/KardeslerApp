# استراتيجية الأمان ونموذج التهديدات والحماية
# Security Architecture & Threat Model

يُعد الأمان المبدأ الأساسي الأول في تصميم نظام **Kardeşler Cihangir**. يوضح هذا المستند نموذج التهديدات المحتملة وآليات التصدي لها، بالإضافة إلى التوافق مع قانون حماية البيانات التركي (KVKK).

---

## 1. نموذج التهديدات وسبل التصدي لها (Threat Model & Mitigations)

| التهديد والسيناريو (Threat) | سيناريو الهجوم (Attack Scenario) | استراتيجية الحماية والتصدي (Mitigation Strategy) |
| :--- | :--- | :--- |
| **1. استنزاف رسائل التحقق (OTP Abuse)** | قيام المهاجم بطلب متكرر لرموز الـ SMS لاستنزاف الرصيد المالي أو تخمين الكود. | - تحديد معدل الطلبات عبر Redis (أقصى حد 3 طلبات كل 10 دقائق لكل رقم هاتف وعنوان IP).<br>- حد أقصى 5 محاولات إدخال خاطئة لكل كود (`attempts <= 5` قيد إلزامي في قاعدة البيانات).<br>- عدم تخزين الأكواد الصريحة مطلقاً؛ يتم حفظ الهاش المشفر فقط (`code_hash`). |
| **2. استغلال الكوبونات والحسابات الوهمية (Coupon Abuse)** | إنشاء حسابات متعددة لإعادة استخدام كوبون الطلب الأول `HOSGELDIN` أو إرسال طلبات متزامنة لتجاوز الحد الأقصى للاستخدام. | - قفل حصري على مستوى السطر (`FOR UPDATE`) في دالة `redeem_coupon()` داخل قاعدة البيانات لمنع الـ Race Conditions.<br>- التحقق من السقف الكلي للاستخدام (`used_count < max_total_uses`) تحت القفل الذري.<br>- قيد فريد (`UNIQUE(order_id)`) يمنع إضافة أكثر من كوبون واحد في الطلب نفسه.<br>- شرط `first_order_only` يتحقق بقوة من عدم وجود أي طلب سابق مُسلّم للعميل في النظام. |
| **3. الوصول غير المصرح به للبيانات (IDOR Protection)** | محاولة عميل قراءة أو تعديل عناوين أو طلبات أو مدفوعات تخص عميلاً آخر. | - حماية متعددة الطبقات (Defense in Depth): Guards في الخادم للتحقق من هوية صاحب الـ JWT.<br>- تفعيل **أمان مستوى السطر في قاعدة البيانات (`FORCE ROW LEVEL SECURITY`)** على جميع الجداول الخاصة بالعملاء.<br>- اتصال الخادم بصلاحيات دور `app_api` المقيد (لا يملك صلاحية تجاوز الـ RLS). في حال غياب هوية الجلسة، تفشل العملية تلقائياً (Fail Closed) وتعود النتيجة بـ 0 أسطر. |
| **4. التلاعب بالمدفوعات وإعادة إرسال الـ Webhooks** | مهاجم يعيد إرسال إشعار الدفع الناجح أو يتلاعب بالمبلغ الإجمالي أثناء التحويل. | - التحقق من التوقيع الرقمي المشفر (HMAC-SHA256 Signature Verification) لجميع إشعارات بوابة الدفع.<br>- قيد فريد على معرف الحدث (`provider_event_id`) يمنع تكرار معالجة نفس الإشعار نهائياً.<br>- التحقق البرمجي الإلزامي من تطابق المبلغ المدفوع مع المبلغ المسجل في الطلب بالقروش (`total_kurus`). |
| **5. سرقة توكن طابعة المطبخ (Compromised Print Agent)** | اختراق جهاز الكمبيوتر في المطبخ أو تسريب التوكن الخاص بوكيل الطباعة. | - وكيل الطباعة يستخدم توكناً محدود الصلاحيات ومخصصاً للقراءة والطباعة فقط (`scope: print:read`) قابل للإلغاء الفوري.<br>- الاتصال خارجي فقط (Outbound-only): وكيل الطباعة يتصل بالخادم لاستقبال المهام، ومنفذ الطابعة 9100 معزول تماماً داخل الشبكة المحلية (LAN) ولا يمكن الوصول إليه من الإنترنت.<br>- التوكن لا يملك أي صلاحية للوصول لبيانات العملاء أو المدفوعات. |
| **6. سرقة حساب أحد موظفي المطعم (Staff Account Takeover)** | وصول غير مصرح به للوحة التحكم عبر التصيد أو اختراق جهاز أحد العاملين. | - تشفير كلمات المرور باستخدام Argon2id وفرض المصادقة الثنائية الإلزامية (TOTP 2FA).<br>- فصل كامل لبيئات وتوكنات الموظفين عن العملاء؛ توكنات الموظفين لا تصلح للتطبيق والعكس.<br>- حفظ الجلسات في ملفات تعريف ارتباط آمنة (`httpOnly`, `Secure`, `SameSite=Strict`) مع الحماية ضد هجمات الـ CSRF.<br>- الإغلاق التلقائي المؤقت للحساب وتنبيه الإدارة عند تكرار محاولات تسجيل الدخول الفاشلة. |

## 2. التوافق مع قانون حماية البيانات التركي (KVKK & IYS Compliance)

1. **حذف وتجهيل بيانات الحساب (`anonymize_user`)**:
   - يحق للعميل طلب حذف حسابه مباشرة من داخل تطبيق الهاتف.
   - تقوم الدالة بمسح رقم الهاتف والاسم والبريد الإلكتروني نهائياً واستبدالها بوسوم مجهولة (`ANON_xxxxxxxx`).
   - يتم حذف العناوين المحفوظة، الأجهزة المسجلة، وجلسات تسجيل الدخول بالكامل.
   - يتم الاحتفاظ بسجلات الطلبات والفواتير كما هي للامتثال للقوانين الضريبية التركية المحاسبية دون ربطها ببيانات شخصية.
2. **سجل الموافقات الثابت (`consents`)**:
   - جدول غير قابل للتعديل (Append-only) يوثق موافقة العميل على الشروط، الخصوصية، ورسائل التسويق (SMS / Push).
   - لا يتم إرسال أي إشعار تسويقي إلا بعد التحقق من وجود موافقة صريحة وسارية.
3. **سجل تدقيق الإدارة (`audit_logs`)**:
   - مشغلات آلية (Triggers) تسجل أي تعديل يجريه موظفو المطعم على أسعار الوجبات، الكوبونات، نطاقات التوصيل، أو حسابات الموظفين.
